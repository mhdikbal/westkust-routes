## 2. D10 POST-FIX ACCOUNTING

From the active 278 D10 rows (`v2a_full_study_recovery_rows.json`,
provenance confirmed in §1):

| quantity | mean | sd |
|---|---|---|
| N_latent | 144.133 | 34.790 |
| N_interval_observed | 121.396 | 29.067 |
| N_estimator_input | 121.396 | 29.067 |

**Invariant check**, all 278 replications:

```
N_estimator_input <= N_interval_observed <= N_latent
violations = 0 / 278
```

**Equality, not just `<=`:** `N_estimator_input == N_interval_observed`
holds exactly in all 278/278 replications (means and sds are identical to
machine precision above because they are the identical per-replication
integers, not merely close). This is **required**, not incidental, given
what D10 actually tests. `N_interval_observed` is defined as
`n_latent - n_unresolved`, i.e. every latent event whose synthetic precision
class is anything other than `"unresolved"` (`exact_day`, `month`, `range`,
`year` — all of which carry a finite `[L,U]` bound). `impute_d10()` performs
a **single random-within-bounds imputation** for every one of those classes
and only drops the `"unresolved"` class (`keep = ~np.isnan(L)`). Since D10's
stress test is specifically about uncertainty from *interval imputation*,
not further data loss at the estimator stage, every interval-eligible event
is guaranteed a point estimate — nothing is dropped between
"interval-observed" and "estimator input" by construction. `N_estimator_input
< N_interval_observed` would only be possible if the estimator itself
discarded some already-resolved events post-imputation, which the current
D10 pipeline never does. Equality is therefore the correct invariant for
this design, and the `<=` in the original request is satisfied as an
equality case.

## 5. RESIDUAL MARGINAL CALIBRATION

```
MARGINAL_KS_SAME_SAMPLE_PARAMETER_ESTIMATION_BIAS = NOT_CALIBRATED
```

The KS statistics and p-values reported in the prior reconciliation
(§1 of `HAWKES_BASELINE_V2_CHECKPOINT5_REVISED_RECONCILIATION.md`) are
preserved exactly as recorded there and are to be read strictly as
**descriptive diagnostics** — evidence about the shape of the fitted-model
residuals, not calibrated hypothesis-test p-values. No new KS computation was
performed in this audit.

**Bootstrap calibration method — specified, NOT executed:**

1. For each design/arm and each observed replication `r` with fitted
   `(mu_hat_r, alpha_hat_r, beta_hat_r)`:
   a. Simulate `K` parametric-bootstrap datasets from the **fitted** model
      `(mu_hat_r, alpha_hat_r, beta_hat_r)` (same simulator, same `T`, same
      `mu_of_t` shape as the arm being calibrated) using a seed derived
      deterministically from `(design_id, rep, bootstrap_index)` — extending
      the same `DESIGN_SEED_OFFSET` scheme from §1 of the prior pass, never
      `hash()`.
   b. Re-fit the Hawkes model to each bootstrap dataset, obtaining
      `(mu_hat_r_b, alpha_hat_r_b, beta_hat_r_b)`.
   c. Compute the time-rescaling residuals and KS statistic
      `D_r_b` for each bootstrap refit **against its own re-estimated
      parameters** (i.e. repeat the full fit-then-test procedure inside each
      bootstrap sample, not against `(mu_hat_r, alpha_hat_r, beta_hat_r)`).
   d. The calibrated p-value for the original replication `r` is
      `p_r = (1 + #{b : D_r_b >= D_r_observed}) / (K + 1)`.
2. Recommended `K`: 199 or 499 per replication (Monte Carlo cost scales as
   `K × 278 × (#designs)`; 199 keeps the smallest attainable calibrated
   p-value at 1/200 = 0.005, adequate for the ≥0.05 decision boundary already
   in use).
3. This procedure is **not to be run without separate authorization**, since
   even the reduced RECOVERY-family scope (4 designs × 278 reps × K bootstrap
   refits each) multiplies total Hawkes-fitting calls by `K`, materially
   larger than either prior targeted rerun.

## 6. RESIDUAL INDEPENDENCE — SPECIFICATION ONLY (NOT EXECUTED)

```
V_T = NOT_COMPLETE
```

Specification, fixed here before any results are observed (no lag selection
after the fact):

- **Diagnostic:** sample autocorrelation function (ACF) of the
  time-rescaling residuals `v_i` (or equivalently the log-transformed
  `-log(1-v_i)` unit-exponential increments `z_i`, whichever the residual
  series already produced by `time_rescaling_residuals()` — use `v_i`
  directly since that is what is already stored), plus the Ljung–Box
  portmanteau test (Ljung & Box, 1978, *Biometrika* 65(2):297–303) for joint
  serial independence.
- **Exact lags:** fixed in advance at `h ∈ {1, 2, 5, 10}`. Rationale: lag 1
  catches immediate excitation-kernel misspecification (the most likely
  failure mode for an exponential-kernel Hawkes fit); lag 5 and 10 are fixed
  a priori as generic short/medium-range checks, chosen before any data are
  examined, not tuned to this dataset.
- **Short event sequences:** the Ljung–Box statistic requires `n > h`;
  per the design registry's own `n_events` distributions (§ achieved-count
  tables in the prior reconciliation), the smallest recorded `n_events` in
  the recovery family is D8's replications, minimum observed count
  well above 10 in every design once contextualized against the achieved
  distributions — but no per-replication floor has yet been enforced. Policy:
  any replication with `n_events <= 10` is excluded from the Ljung–Box
  computation at lag 10 (and correspondingly for lags exceeding `n_events`),
  and the excluded count is reported alongside the diagnostic, never silently
  dropped.
- **Multiplicity / reporting policy:** 4 lags × up to 5 design/arms = up to
  20 Ljung–Box p-values. No single omnibus decision rule is imposed; each
  lag's `frac_below_0.05` across the 278 replications is reported
  separately per design/arm, exactly as the KS diagnostic already is,
  together with a Bonferroni-adjusted threshold (`0.05/4 = 0.0125` per
  design/arm across the 4 lags) offered as one interpretive aid, not as a
  single collapsing pass/fail statistic.

**This diagnostic is specified but not implemented or executed under this
audit.** Until it runs, `V_T` remains `NOT_COMPLETE` and residual validation
for H-05 cannot be considered closed by the marginal KS check alone (§5).

## 7. ONTOLOGY CONTRACT

Formal event-type distinction, scoped to what V2-A actually manipulates
(synthetic-only) versus what any future historical application would need to
map onto it:

| Type | Definition |
|---|---|
| `LATENT_HISTORICAL_EVENT` | An event that actually occurred in history, whether or not any surviving document reports it. Never directly observed by any process in this repository. |
| `DOCUMENTED_OR_REPORTED_EVENT` | A `LATENT_HISTORICAL_EVENT` that was recorded by a contemporary source, subject to that source's own survival, access, and reporting biases. Strictly a subset of `LATENT_HISTORICAL_EVENT`. |
| `CORPUS_CODED_EVENT` | A `DOCUMENTED_OR_REPORTED_EVENT` that a researcher has located, read, and coded into the project's structured corpus (e.g. the 141-event precision-class distribution `PRECISION_PROPORTIONS` used to calibrate D4/D10). Strictly a subset of `DOCUMENTED_OR_REPORTED_EVENT`. |
| `PARENT_EPISODE` | A `CORPUS_CODED_EVENT` (or cluster thereof) treated as the triggering/parent point of a cluster process (D6's Neyman–Scott parents); a modeling role, not an independent ontological class. |
| `SYNTHETIC_GENERATED_EVENT` | An event produced by a V2-A simulator (`simulate_poisson`, `simulate_exp_hawkes`) from a fully specified, known synthetic DGP. Has no historical referent whatsoever. This is the *only* event type any V2-A design generator (`gen_D1`...`gen_D9`, `gen_D10_latent`) actually produces. |
| `OBSERVED_SYNTHETIC_EVENT` | A `SYNTHETIC_GENERATED_EVENT` after a design's observation mechanism has been applied (D5's `p_obs` thinning; D10's precision-class assignment and interval generation). Strictly a subset of `SYNTHETIC_GENERATED_EVENT`. |
| `ESTIMATOR_INPUT_EVENT` | The event array actually passed to `fit_hawkes()` / `fit_homogeneous_poisson()` / `fit_inhomogeneous_poisson_cd()`. For most designs `ESTIMATOR_INPUT_EVENT == OBSERVED_SYNTHETIC_EVENT` (or `== SYNTHETIC_GENERATED_EVENT` where no observation mechanism is applied); for D10 specifically it is the post-imputation array (`n_estimator_input`, §2). |

**Mapping recorded:**

```
N_corpus(t) = O{ H(t), observation, survival, access, coding }
```

read as: the count of `CORPUS_CODED_EVENT`s at time `t` is the image of the
true `LATENT_HISTORICAL_EVENT` process `H(t)` under the composed operator of
(i) whatever generated a contemporary observation, (ii) whether that
observation's physical/documentary record survived, (iii) whether a
researcher had access to that surviving record, and (iv) whether that
accessed record was actually coded into the corpus. Each stage is lossy and
non-random with respect to `t` (the entire premise of D3's exposure-covariate
design and D5's density-thinning design is that this loss correlates with
real historical document density, not with `t` alone).

**Explicitly prohibited:**

```
N_corpus(t) = H(t)     -- FORBIDDEN
```

No result in V2-A, the prior reconciliation, or this audit treats the
corpus-coded count as equal to the true latent historical event count. Every
V2-A design generates and fits `SYNTHETIC_GENERATED_EVENT` /
`OBSERVED_SYNTHETIC_EVENT` / `ESTIMATOR_INPUT_EVENT` data exclusively (per
`v2a_validation_engine.py`'s own docstring: "Uses SYNTHETIC data only. Never
reads, fits, or interprets the 86-event historical primary analysis set...").
This ontology contract governs any *future* step that would connect V2-A's
validated estimator behavior to the actual historical corpus — that step has
not been taken by V2-A and is out of this audit's scope.

## 8. CAUSAL BOUNDARY

Recorded explicitly, to bound interpretation of every result in the prior
reconciliation and this audit:

**V2-A validates estimator behavior under prespecified synthetic
data-generating processes (DGPs).** It establishes, for each of D1–D10: how
often a fitted Hawkes model is statistically preferred over a stated
comparator when the *synthetic* truth is known (D1–D6); how well MLE
recovers known parameters, and how well finite-difference-Hessian Wald CIs
cover the known truth, again under a *known synthetic* DGP (D7–D10).

**V2-A does not identify, and no result in this file or the prior
reconciliation should be read as evidence of:**
- historical causality between any two real events;
- resistance contagion or diffusion in the historical record;
- event-to-event transmission mechanisms;
- the endogenous share of historical events attributable to
  self-excitation versus exogenous causes;
- the effect of any intervention, historical or counterfactual.

**Hawkes preference over Poisson, wherever reported (D1–D6), is
model-selection evidence only within the specific candidate model set
compared** (homogeneous Poisson, inhomogeneous Poisson, or the stated
Hawkes specification) **and only under the synthetic DGP each design
constructs.** It says nothing about whether a Hawkes process is the correct
description of any real historical process, nor whether self-excitation "is
present" in history, until and unless a separate, explicitly authorized step
applies a validated estimator to the actual `CORPUS_CODED_EVENT` data and
that step's own assumptions (identical censoring/coding/exposure structure
to a validated design) are independently justified.
